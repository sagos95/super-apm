# super-apm

[![English](https://img.shields.io/badge/English-57606A?style=flat&logo=googletranslate&logoColor=white)](README.md)
[![Русский](https://img.shields.io/badge/%D0%A0%D1%83%D1%81%D1%81%D0%BA%D0%B8%D0%B9-0969DA?style=flat&logo=googletranslate&logoColor=white)](README.ru.md)

Оболочка над [Microsoft APM](https://github.com/microsoft/apm) для общих и локальных скиллов, MCP-серверов и хуков в Claude Code и Codex.

## Зачем это нужно?

У вас есть личный скилл, MCP или хук, и вы хотите использовать его в проекте с APM (Agent Package Manager), но не хотите, чтобы скилл попал в Git и им пользовались другие участники проекта? Тогда Super-apm для вас!

В обычной ситуации, если добавить ИИ-инструмент в APM-зависимости проекта, то инструмент будет автоматически устанавливаться у всех пользователей проекта.

Вместо этого Super-apm подключает такой инструмент (скилл, MCP или хук) только для вас. Агент может использовать его в проекте, а файлы инструмента и личные настройки будут исключены из Git.

Super-apm позволяет устанавливать и обновлять как командные инструменты, так и свои дополнения сразу одной командой.

- **Shared — общие:** список пакетов в `apm.yml`, хранится в Git вместе с проектом.
- **Local — локальные:** пакеты в `.apm-local/`, автоматически исключены из Git вместе с созданными ссылками и конфигами.
- **Upstream — снимки из приватного источника:** папка, которой весь проект пользуется из Git, а обновляете её только вы, из своего приватного источника. Где лежит источник, записано в `.apm-local/`, поэтому участники видят папку, но не знают, откуда она приходит.
- **Hidden — скрытые зависимости:** скиллы, которые нужны пакету, но не должны быть видны агенту. Они лежат в исключённой из Git папке `.apm-hidden/` под другим именем файла.

## Установка

Нужны Python 3.11+, Git, uv и APM на PATH. Проверено с APM 0.32.0.

```sh
uv tool install 'git+https://github.com/sagos95/super-apm.git@v0.8.0'
```

## Использование

Запускайте из своего проекта:

```sh
super-apm install owner/package          # добавить общий пакет
super-apm install owner/package --local  # добавить локальный пакет
super-apm install                        # установить оба набора
super-apm update --yes                   # обновить оба набора
super-apm list                           # показать все пакеты
super-apm status                         # проверить ссылки и фоновое обновление
```

Добавьте `--shared` или `--local`, чтобы работать только с одним набором. Автоматических коммитов и пушей нет.

## Поделиться инструментом из приватного источника

Скилл, который вы ведёте в другом месте, можно положить в проект так, чтобы участники получали его из Git, а обновляли его только вы:

```sh
super-apm upstream add .apm/skills/my-skill --source ~/path/to/private-repo --subpath skills/my-skill
super-apm upstream sync    # скопировать в снимок закоммиченную версию из источника
```

`--source` принимает локальный клон Git или адрес Git-репозитория. Копируются только закоммиченные изменения. Папку снимка коммитьте как обычно, а путь к источнику, адрес и состояние синхронизации остаются в `.apm-local/`, исключённой из Git. Если стоят хуки сессии, снимки обновляются перед каждой фоновой установкой. Снимок, который поправили прямо в проекте, super-apm не перезаписывает.

## Скрытые зависимости для скиллов-роутеров

Скилл-роутер выбирает один метод из многих и читает только его. Если поставить методы как обычные скиллы, в список скиллов агента добавятся десятки описаний. Claude Code и Codex отводят под этот список 1–2% окна контекста, и описания перестанут в него помещаться. Поэтому роутер объявляет методы в своём `apm.yml`:

```yaml
name: ux-router
version: 1.0.0
super-apm:
  hidden:
    destination: references/methods            # папка внутри .apm-hidden/ux-router/
    rename: {SKILL.md: METHOD.md}              # значение по умолчанию; SKILL.md оставлять нельзя
    dependencies:
      - emilkowalski/skills/skills/animate#64eb3de
      - {package: owner/repo/plugins/ux-strategy/skills/frame-problem, as: ux-strategy/frame-problem}
      - path: ../ux-check                      # путь от исходников пакета
```

`super-apm install` кладёт каждый метод в `.apm-hidden/ux-router/references/methods/<имя>/METHOD.md`, остальные файлы папки остаются как в источнике. `update` и ежедневные хуки сессии обновляют методы вместе с обычными пакетами. `list` показывает их коммиты, `status` проверяет файлы, а при удалении роутера методы уходят в Корзину. Зависимости записываются в обычных форматах APM, включая приватные хосты и закреплённые `#ref`. Ключ `as` задаёт имя папки, по умолчанию берётся имя самого скилла.

Роутер находит методы, поднимаясь вверх от своей папки; при глобальной установке (`super-apm install -g`) они лежат в `~/.apm/.apm-hidden/`:

```python
from pathlib import Path

def hidden_dir(package: str) -> Path | None:
    for folder in Path(__file__).resolve().parents:
        if (folder / ".apm-hidden" / package).is_dir():
            return folder / ".apm-hidden" / package
    global_dir = Path.home() / ".apm" / ".apm-hidden" / package  # super-apm install -g
    return global_dir if global_dir.is_dir() else None
```

Почему устроено именно так:

- **Список лежит в `apm.yml` пакета.** APM 0.32 пропускает ключ `super-apm`, поэтому у пакета остаётся один манифест и он по-прежнему ставится обычным APM. Список нарочно вынесен из `dependencies.apm`, потому что оттуда APM поставил бы методы как видимые скиллы.
- **Файлы лежат в `.apm-hidden/`, а не внутри установленного пакета.** APM переписывает `.claude/skills/<пакет>` при каждом `apm install` и стирает файлы, которые положил не он.
- **Скачивает их всё равно APM.** super-apm запускает `apm lock` в отдельной рабочей папке. Эта команда находит версии, скачивает пакеты и записывает lockfile, но ничего не раскладывает по папкам агентов. Lockfile лежит в `.apm-hidden/.super-apm/<пакет>/`.
- **Код пакета не запускается.** super-apm только скачивает, копирует и переименовывает файлы.

Без super-apm роутер ставится без своих методов. Lockfile у каждой машины свой, поэтому закрепляйте `#ref`, если всем машинам нужны одинаковые версии. Остальные правила описаны в [подробном руководстве](docs/advanced.md#hidden-dependencies).

## Автообновление

```sh
super-apm hooks install --shared-policy daily
```

При старте сессии агента пакеты и их скрытые зависимости обновляются в фоне раз в сутки. Чтобы сохранить закреплённые общие версии, используйте `--shared-policy pinned`; локальные пакеты продолжат обновляться ежедневно.

Одобрите изменённые хуки в Codex и перезапустите сессию агента.
